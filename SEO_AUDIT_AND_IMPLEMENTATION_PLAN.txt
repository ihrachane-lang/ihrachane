IHRACHANE SEO AUDIT & IMPLEMENTATION PLAN
==========================================
Audit date: 2026-08-06
Scope: Repository source, production build output, routes, metadata, structured data,
indexing controls, content architecture and a limited public-search check.

EXECUTIVE SUMMARY
-----------------
The application has a solid technical starting point: server-rendered/SSG public pages,
canonical URLs, robots.txt, a dynamic sitemap, descriptive image alt text, breadcrumbs,
and basic Organization/Service/FAQ structured data already exist. The production build
completed successfully.

It is not currently set up to reliably rank for Turkish and English commercial queries.
The main gap is not a missing meta-keyword list; it is language and content architecture.
One English canonical page mixes English and Turkish copy, while no equivalent Turkish URLs
or hreflang relationships exist. This gives search engines no clear Turkish landing page to
rank. Generic, repeated service copy and limited proof/E-E-A-T signals also make it hard to
compete with established sourcing/logistics websites.

No ethical SEO process can guarantee a #1 result. Organic rank depends on relevance,
technical quality, real expertise, competitor strength, geographic intent, backlinks,
brand demand and user behaviour. The plan below maximizes the chances of first-page
visibility and creates the conditions needed to compete for top positions.

CONFIRMED FINDINGS (SOURCE AND BUILD EVIDENCE)
------------------------------------------------

P0 - Fix before the next release

1) Turkish targeting is structurally incomplete.
   Evidence: Root HTML is lang="en"; root metadata advertises only `en` and `x-default`
   alternates; dynamic and static public pages have a single canonical English URL. The
   visible `BilingualSeoSection` merely adds Turkish copy to those same URLs. `og:locale`
   is en_US, with tr_TR declared only as an Open Graph alternate.
   Impact: Search engines cannot reliably associate a separate Turkish version with Turkish
   searches. Mixed-language pages also produce weaker language relevance and can confuse
   snippets.
   Required fix: create dedicated, indexable Turkish routes (for example /tr/, /tr/cin-
   tedarik/, /tr/cinden-turkiyeye-lojistik/) with human-written Turkish content. Add
   reciprocal alternate links on every English/Turkish pair:
   - hreflang="en" -> English URL
   - hreflang="tr" -> Turkish URL
   - hreflang="x-default" -> the preferred default URL
   Set document lang correctly per route and list all localized URLs in the sitemap.
   Keep English as the default site language; Turkish pages are search landing pages, not a
   requirement to make the entire user interface Turkish.

2) Some generated page titles duplicate the brand and titles/descriptions are cut off.
   Evidence: `clampTitle()` already appends " | IHRACHANE", while the root title template
   also appends " | IHRACHANE". The generated category page title contained
   "... | IHRACHANE | IHRACHANE". `clampTitle()`/`clampDescription()` truncate by characters,
   creating output such as `Logistics...` and `Teda...` in generated HTML.
   Impact: lower SERP click-through rate, unprofessional snippets and weaker keyword clarity.
   Required fix: have exactly one owner append the brand (normally the root metadata title
   template). Page functions should return a clean page-specific title. Replace character
   clipping with manually written titles/descriptions, reviewed at rendered-output level.

3) An invalid SearchAction schema points to a route that does not exist.
   Evidence: `websiteJsonLd()` declares https://www.ihrachane.com/search?q={search_term_string},
   but the application has no `/search` route.
   Impact: invalid/misleading structured data and no SEO benefit.
   Required fix: remove SearchAction until a real, crawlable internal search feature exists.

4) Sitemap freshness can be wrong after content changes.
   Evidence: the slug-backfill API imports `sitemapChanged`, but this function is not exported
   from `src/lib/revalidate-public.js`. Next build warns about the attempted import. The
   same helper is private despite being used by that route.
   Impact: category/slugs/sitemap may stay stale until ISR refreshes, delaying discovery and
   preserving outdated URLs.
   Required fix: export the helper or stop importing it and use a supported public revalidation
   function. Add an integration test that updates a category/subcategory and verifies the
   current URL and sitemap entry are refreshed.

5) The audit build contains obviously non-production category data.
   Evidence: the generated build included routes/content such as `/raebyrd/quia-porro-porro-lab`
   and a "Shippings" category.
   Impact: if this database/configuration is deployed, low-quality placeholder pages can be
   indexed and damage topical relevance and trust.
   Required fix: audit the production CMS database before indexing; delete or noindex any test,
   empty, duplicate, expired or internal pages. Use a staging database for development builds.

P1 - High-value technical SEO improvements

6) Structured data needs to describe the actual business more accurately.
   - Organization schema has `sameAs: []`; it does not include verified social profiles,
     address, telephone, contactPoint, founding information or area served even though some
     details are available in the footer/CMS.
   - Subcategory pages use Product + an Offer with price `0` although the business appears to
     sell sourcing services/quotes, not the named physical products. Use Service, OfferCatalog
     or ItemList markup unless a real purchasable product, price and availability exist.
   - Generic FAQ markup is repeated per category. FAQ schema is not a ranking lever and Google
     commonly limits FAQ rich results. Keep only visible, specific FAQs that users genuinely
     ask; do not create them only for markup.
   - Validate every template with Google Rich Results Test and Schema.org Validator after release.

7) Crawl controls should be tightened.
   Evidence: robots.txt disallows `/dashboard/` and `/api/`, and dashboard/auth metadata is
   noindex. But `/login`, `/register`, `/reset-password` and `/otp-verification` are crawlable
   in robots.txt and are linked by the public footer portal area.
   Required fix: disallow those utility paths in robots.txt if they never need search traffic,
   retain meta robots noindex, and ensure they cannot enter the sitemap. Do not block pages in
   robots.txt before Google has seen their noindex tag if they are already indexed; use Search
   Console removals/noindex first, then consider the crawl rule.

8) Sitemap output should become a complete, truthful URL inventory.
   - Add Turkish alternate URLs and hreflang annotations.
   - Include only 200, canonical, indexable pages.
   - Use the actual CMS `updatedAt`; do not use `new Date()` as a fallback because it falsely
     says every generated URL changed today.
   - Submit sitemap.xml in Google Search Console and Bing Webmaster Tools after deployment.
   - Monitor coverage, excluded URLs, canonical selections and crawl errors weekly.

9) Improve sharing and image SEO.
   Evidence: Open Graph/Twitter images use an SVG logo while claiming 1200x630 dimensions.
   Required fix: create a real 1200x630 PNG/WebP/JPG branded social card with readable text;
   use specific image alt text for every service/category image. Compress oversized local
   assets and ensure Cloudinary transformations serve suitable dimensions and modern formats.

10) Core Web Vitals need measurement, then optimization.
   The build is technically successful, but a build does not measure real-user LCP, INP or CLS.
   Remote images and large visual assets are likely candidates for LCP/weight review. Test the
   deployed English and Turkish home/service URLs with PageSpeed Insights (mobile and desktop).
   Target: LCP <= 2.5s, INP <= 200ms, CLS <= 0.1 at the 75th percentile. Use explicit image
   dimensions, Cloudinary/WebP/AVIF transformations, responsive `sizes`, lazy loading below the
   fold, and minimal third-party scripts.

P1 - Content, relevance and trust gaps

11) Avoid keyword-list thinking and repeated template copy.
   Evidence: long metadata keyword arrays are present on most templates, and the bilingual
   component reuses similar generic paragraphs/keyword chips across category and subcategory
   pages. Google does not use the meta keywords tag as a primary ranking signal.
   Impact: the site risks thin/near-duplicate commercial pages that add little unique value.
   Required fix: retain only natural page copy and replace each indexable page's generic text
   with unique, decision-useful information: target product/category, sourcing countries,
   MOQ range where publishable, factory-audit process, quality standards, lead times, shipping
   modes, documents, constraints, representative case evidence and a tailored CTA.

12) Build topic clusters around real Turkish and English search intent.
   English commercial examples:
   - China sourcing agent for [category]
   - supplier verification China
   - factory audit and quality inspection China
   - China warehouse consolidation / freight forwarding to Turkey
   Turkish commercial examples (must be validated with keyword research before publishing):
   - Çin tedarikçi bulma
   - Çin'den ürün tedarik
   - Çin'den Türkiye'ye lojistik
   - Çin fabrika denetimi
   - Çin kalite kontrol hizmeti
   - Çin depo ve konsolidasyon
   Create one high-quality pillar page per intent, then supporting practical pages. Do not make
   one page for every keyword variation; map one primary intent per URL.

13) Establish E-E-A-T and B2B trust signals.
   Add a full company profile: legal business name, operating locations, team members and
   relevant experience, service process, insurance/certifications where factual, partner/carrier
   evidence, client permissioned case studies, named testimonials, sample inspection report,
   service-level expectations, terms, privacy, contact details and a clear response time.
   Put the same verified NAP/contact information on site, Organization schema, Google Business
   Profile (where eligible) and reputable industry profiles.

14) Internal linking needs a deliberate hub model.
   Keep a permanent top navigation/footer path to service pillars. Each category page should
   link to relevant subcategories, guides, case studies and quote pages with descriptive anchor
   text; each guide should link back to the applicable commercial service. Avoid orphan pages.
   Breadcrumbs are already a good start.

P2 - Authority and measurement

15) Off-page authority is essential for competitive #1 goals.
   Earn relevant, editorial links rather than buying links: supplier/trade association listings,
   logistics/commerce publications, partner pages, Turkish trade publications, original data or
   checklists, client case studies and expert interviews. Prioritize topical relevance and real
   referral value. Never use link farms, PBNs, automated comments, doorway pages, hidden text
   or copied AI content.

16) Analytics and conversion measurement are missing from the audited source.
   Add a consent-aware analytics setup and Search Console. Track organic landing page, country,
   language, query group, form start/submission, WhatsApp/call/email clicks and qualified lead
   outcome in a CRM. SEO should be judged by qualified enquiries and revenue, not rank alone.

ENGLISH + TURKISH INFORMATION ARCHITECTURE
-------------------------------------------
Recommended model: English default, Turkish localized search landing pages.

  /                                English home (x-default + en)
  /services/sourcing/               English sourcing service
  /services/quality-inspection/     English inspection service
  /services/china-to-turkey-freight/English route-specific logistics service
  /industries/[industry]/           English industry/category pages
  /resources/[article]/             English guides/case studies

  /tr/                              Turkish home (tr)
  /tr/cin-tedarik/                  Turkish sourcing service
  /tr/cin-fabrika-denetimi/         Turkish audit/QC service
  /tr/cinden-turkiyeye-lojistik/    Turkish route-specific logistics service
  /tr/sektorler/[sector]/           Turkish industry/category pages
  /tr/rehber/[article]/             Turkish guides/case studies

Each paired page needs equivalent intent, not a word-for-word duplicate. Canonical must point
to itself in the same language; never canonicalize Turkish pages to English. Use normal HTML
links for the language selector, not automatic IP/language redirects. Keep forms and operations
in English if required, but localize the explanatory landing-page copy and CTA labels.

90-DAY IMPLEMENTATION PLAN
--------------------------

Phase 0: Baseline and decisions (Days 1-5)
1. Confirm primary markets, target buyer personas, actual service locations and the commercial
   goal (lead quality, category, Turkey route, or global clients).
2. Add/verify Google Search Console, Bing Webmaster Tools, GA4/consent and conversion events.
3. Crawl the deployed site with Screaming Frog/Sitebulb and export: status codes, canonicals,
   titles, descriptions, H1s, indexability, images and internal links.
4. Export Search Console query/page/country data; benchmark current rankings against real
   Turkish and English competitors. This audit could not confirm live indexing because the
   public URL/robots/sitemap fetch was unavailable from the audit environment and the limited
   public search check did not surface IHRACHANE results.
5. Approve the English/Turkish URL map and prevent test CMS data from being indexable.

Phase 1: Technical foundation (Days 6-15)
1. Fix the title ownership/duplication and rewrite priority titles/descriptions.
2. Remove invalid SearchAction; correct Product/Offer use; enrich Organization/LocalBusiness
   or Organization schema with only verified data.
3. Fix the missing `sitemapChanged` export/import and test cache invalidation.
4. Add real social-card images, favicons/manifest icons, self-canonical metadata, and any
   missing `noindex` utility-page controls.
5. Produce and validate sitemap, robots, redirects and structured data in staging.
6. Run PageSpeed Insights and fix the most material mobile LCP/CLS problems.

Phase 2: Localization and core landing pages (Days 16-35)
1. Implement `/tr` routing, localized metadata, lang attributes, reciprocal hreflang and
   sitemap alternates.
2. Publish 4-6 high-intent English service pages and their Turkish counterparts, starting with
   sourcing, supplier verification, factory audit/quality control, warehousing/consolidation,
   China-to-Turkey freight and one highest-value industry.
3. Write unique content from subject-matter experts; include concrete process/proof and FAQs
   visible on the page.
4. Build contextual internal links and a language switcher.

Phase 3: Topical authority and conversion (Days 36-65)
1. Publish 8-12 useful resources split by language: import/sourcing checklists, factory-audit
   guides, freight-document explainers, route lead-time guides and category sourcing guides.
2. Add two genuine, permissioned case studies and a transparent "How we work" page.
3. Improve quote forms by service/route/category, preserve attribution and track qualification.
4. Obtain and validate business profiles/citations; begin editorial digital PR and partner-link
   outreach with useful assets, not reciprocal-link schemes.

Phase 4: Iterate from data (Days 66-90 and ongoing)
1. Weekly: inspect indexing, sitemap errors, CWV and page experience in Search Console.
2. Monthly: map impressions -> clicks -> qualified leads by language, page and query cluster.
3. Improve pages with high impressions/low CTR first; expand pages already gaining qualified
   impressions; merge/noindex weak duplicates.
4. Continue publishing expert content and earning authoritative mentions. Expect competitive
   non-brand commercial terms to need sustained work over months, not days.

SUCCESS METRICS
---------------
Technical (within 30 days): all intended public pages indexable/200/self-canonical, zero
structured-data errors, valid hreflang reciprocity, accurate sitemap and no utility-page index.

Visibility (within 90-180 days, dependent on authority): growing non-brand impressions and
top-20 then top-10 positions for the priority Turkish/English intent clusters; brand searches
consistently return the official domain first.

Business: qualified organic quote requests, calls and WhatsApp conversations by service and
market, with conversion rate and pipeline value reported monthly.

VERIFICATION COMPLETED
----------------------
- `npm run build` passed and rendered the public routes.
- The build produced one actionable module-import warning and duplicate Mongoose index warnings.
  The Mongoose warnings are not a direct ranking issue, but should be cleaned up for operational
  quality.
